# Архитектура Meteora DLMM Radar

Этот документ описывает **компоненты и принципы работы**, а не конкретную версию скрипта. История изменений ведётся отдельно в `CHANGELOG.md`.

## 1. Получение данных

1. **Поиск пулов:** Meteora Discovery и резервный источник списка DLMM-пулов; периодический опрос, пагинация.
2. **Отбор:** проверка типа DLMM, возраста, капитализации, базовой комиссии и комиссий выбранного временного окна.
3. **Текущий снимок:** данные конкретного пула и показатели Discovery за 30 минут; информация разных окон не должна смешиваться.
4. **Обогащение:** GMGN — метаданные и доступные показатели безопасности; InsightX — кластеры, Scanner и метки; DEX Screener — доступные ссылки X; Solana RPC — отдельные технические проверки (например, Bin Rent, Transfer Fee).
5. **Расчёты:** отношения комиссий и объёма к Active TVL, цветовые пороги риска, исключение распознанных технических адресов из кандидатов Top Wallet.
6. **Хранение:** SQLite для пулов, оригинальных снимков карточек и данных, позволяющих определить нужный пул при нажатии кнопки.
7. **Отправка:** Pillow создаёт PNG из двух таблиц, Telegram Bot API отправляет карточку и кнопки.

## 2. Как устроены две таблицы

- **Верхняя таблица:** неизменяемый снимок первоначальной карточки. Заголовок MC при обновлении может показывать «было → стало».
- **Нижняя таблица:** свежие значения на момент нажатия кнопки. На первой карточке часть полей нижней таблицы остаётся пустой.
- **Update:** использует текущие данные Meteora за **30 минут**, а проценты изменения считает относительно первого снимка.
- **Update 30MIN:** также использует текущие данные Meteora за **30 минут**, но берёт 30-минутные процентные изменения, возвращаемые Meteora.
- Неполный ответ Discovery не должен заменять текущую карточку выдуманными значениями.
- Top Wallet и Honeypot обновляются с кешированием около **120 секунд**, чтобы не расходовать лимит InsightX на каждый клик.
- Успешное обновление **редактирует исходное сообщение Telegram**.

## 3. Исполнение и надёжность

- Python работает на Windows 11 и запускается через `Start_Radar.bat` / ярлык по необходимости.
- Защита единственного экземпляра предотвращает двойной запуск и конфликт Telegram `getUpdates`.
- Обработчик Telegram работает параллельно основному циклу обнаружения пулов.
- SQLite хранит сведения о впервые увиденных пулах и отправленных карточках; предусмотрены механизмы предотвращения повторной отправки.
- Ошибки дополнительных источников должны приводить к `н/д`, а не к ложному значению `0`.

## 4. Известные ограничения

- InsightX иногда возвращает пустой список держателей даже с HTTP 200; Top Wallet тогда недоступен.
- Отсутствие метки кошелька не означает, что адрес независимый или нетехнический.
- Bubble MAX / OTHER вычисляются по InsightX; они не обязаны совпадать с визуальной картой Bubblemaps.
- Ссылки X на отдельные упоминания доступны, только когда источник действительно возвращает URL публикации.
- Для нескольких пулов одного токена метрики держателей совпадают, а параметры пула могут отличаться.

## 5. Граница публикации

Публичная копия GitHub создаётся отдельно. `.env`, приватные ключи `.pem`, API-токены, SQLite-базы, логи и резервные копии **не публикуются**.
